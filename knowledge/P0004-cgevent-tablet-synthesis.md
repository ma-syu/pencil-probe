Apple Developer Documentation サイトは JavaScript 必須で取得できなかった。

|---|---|

| IOLLEvent.h | IOKit.framework/Headers/hidsystem/IOLLEvent.h |
| NSEvent.h | AppKit.framework/Headers/NSEvent.h |

## 1. 筆圧フィールドは 2 つある

| フィールド | ID | 型 | 範囲 | ヘッダの記述 |
|---|---|---|---|---|
| `kCGMouseEventPressure` | 2 | double | 0.0–1.0 | "mouse button pressure… commonly set by tablet pens mimicking a mouse" |
| `kCGTabletEventPointPressure` | 19 | double | 0.0–1.0 | "tablet pen pressure. 0.0 = no pressure, 1.0 = maximum pressure" |

`NSEvent.pressure`（float）は全 mouse down/up/drag イベントで有効。
アプリがどちらを見るかはヘッダからは確定できない。
**合成時は両方を設定し、どちらか一方で通るか実験で確認する。**

下層（`NXTabletPointData.pressure`）は UInt16 0–65535。
CGEvent API が 0.0–1.0 へのスケーリングを行う。

---

## 2. Tilt の値域

| 情報源 | 記述 | 範囲 |
|---|---|---|
| CGEventTypes.h（field 20, 21） | "0 = no tilt, 1 = maximum tilt" | 0–1（文面通り） |
| NSEvent.h（tilt プロパティ） | "range is -1 to 1 for both axes" | **-1 to 1** |
| IOLLEvent.h（NXTabletPointData.tilt） | SInt16, "-((2^15)-1) to (2^15)-1" | -32767–32767 |

**CGEventTypes.h の記述は不完全。** 下層が符号付き 16bit であり、
NSEvent が -1 to 1 と明記しているため、実際の範囲は **-1.0 to 1.0**。
CGEventTypes.h は正の最大値しか言及していない。

## 3. Subtype の設定は他のフィールドより先

CGEvent.h `CGEventSetIntegerValueField` のコメント（原文）:

> If you are creating a mouse event generated by a tablet, call this
> function and specify the field `kCGMouseEventSubtype` with a value of
> `kCGEventMouseSubtypeTabletPoint` or `kCGEventMouseSubtypeTabletProximity`
> **before setting other parameters**.

| 定数 | 値 | 意味 |
|---|---|---|
| `kCGEventMouseSubtypeDefault` | 0 | 通常のマウス |
| `kCGEventMouseSubtypeTabletPoint` | 1 | タブレットポイント |
| `kCGEventMouseSubtypeTabletProximity` | 2 | タブレット接近/離脱 |

## 4. Proximity イベントの必要性

### ヘッダが明示していること

- `kCGTabletProximityEventEnterProximity`（field 38）:
  "non-zero if pen is in proximity to the tablet and zero when leaving"
- proximity イベントは `capabilityMask` を運ぶ。このマスクが
  アプリにデバイスの能力（筆圧対応、傾き対応など）を伝える
- NSEvent.h: `deviceID` は tabletPoint と tabletProximity の**両方で有効**

### ヘッダが明示していないこと

- proximity イベントを送らずに tabletPoint だけ送って動くかどうか
- proximity を先に送る順序の強制

### 推測（未確認）

アプリは通常、proximity イベントで tablet モードに入り、
capabilityMask を見て受け付けるフィールドを決める。
**proximity なしだと筆圧が無視される可能性がある。**
Phase 1 では proximity あり/なしの両方を検証する。

## 5. Proximity イベントのフィールド

| フィールド | ID | 型 | 説明 |
|---|---|---|---|
| `kCGTabletProximityEventVendorID` | 28 | int | USB vendor ID（通常） |
| `kCGTabletProximityEventTabletID` | 29 | int | USB product ID（通常） |
| `kCGTabletProximityEventPointerID` | 30 | int | ポインティングデバイス ID |
| `kCGTabletProximityEventDeviceID` | 31 | int | **システム割当のデバイス ID** |
| `kCGTabletProximityEventSystemTabletID` | 32 | int | システム割当のタブレット ID |
| `kCGTabletProximityEventVendorPointerType` | 33 | int | ベンダー定義ポインタ種別 |
| `kCGTabletProximityEventVendorPointerSerialNumber` | 34 | int | シリアル番号 |
| `kCGTabletProximityEventVendorUniqueID` | 35 | int | ベンダー定義一意 ID |
| `kCGTabletProximityEventCapabilityMask` | 36 | int | **デバイス能力マスク** |
| `kCGTabletProximityEventPointerType` | 37 | int | ポインタ種別 |
| `kCGTabletProximityEventEnterProximity` | 38 | int | 1=接近, 0=離脱 |

### ポインタ種別（IOLLEvent.h）

| 定数 | 値 |
|---|---|
| `NX_TABLET_POINTER_UNKNOWN` | 0 |
| `NX_TABLET_POINTER_PEN` | 1 |
| `NX_TABLET_POINTER_CURSOR` | 2 |
| `NX_TABLET_POINTER_ERASER` | 3 |

### 能力マスク（IOLLEvent.h）

Phase 1 で最低限必要なもの:

| 定数 | 値 | 意味 |
|---|---|---|
| `NX_TABLET_CAPABILITY_DEVICEIDMASK` | 0x0001 | デバイス ID |
| `NX_TABLET_CAPABILITY_ABSXMASK` | 0x0002 | 絶対 X 座標 |
| `NX_TABLET_CAPABILITY_ABSYMASK` | 0x0004 | 絶対 Y 座標 |
| `NX_TABLET_CAPABILITY_BUTTONSMASK` | 0x0040 | ボタン |
| `NX_TABLET_CAPABILITY_TILTXMASK` | 0x0080 | 傾き X |
| `NX_TABLET_CAPABILITY_TILTYMASK` | 0x0100 | 傾き Y |
| `NX_TABLET_CAPABILITY_PRESSUREMASK` | 0x0400 | **筆圧** |

Phase 1 の最小マスク: `0x0587`（上記 7 つの OR）。

## 6. DeviceID の扱い

- CGEventTypes.h: "**system-assigned** unique device ID"（field 24, 31）
- 下層（NXTabletPointData/NXTabletProximityData）では UInt16

「system-assigned」は通常、実デバイスが接続されたときに OS が振る ID。
合成イベントでは実デバイスが存在しないため、任意の値で通るかは**未確認**。

**Phase 1 での検証方針**: 小さい正の整数（例: 1）を使い、
proximity と point で同じ値を一貫して使う。

---

## 7. Mouse イベントと TabletPoint の関係

タブレットデータの配送には 2 つの形式がある。

### (a) Mouse イベント + tablet subtype（主流）

イベント種別は通常の mouse（`kCGEventLeftMouseDown` 等）だが、
`kCGMouseEventSubtype` が `kCGEventMouseSubtypeTabletPoint`（1）に設定され、
tablet フィールド（筆圧・傾き等）が埋め込まれる。

NSEvent.h はこの形式を随所で言及:
> "valid for mouse events with subtype NSEventSubtypeTabletPoint,
> and for NSEventTypeTabletPoint events"

### (b) スタンドアロン tablet イベント

イベント種別が `kCGEventTabletPointer`（23）/ `kCGEventTabletProximity`（24）。
IOLLEvent.h の定義では "for non-mousing transducers"。

### Phase 1 の方針

**(a) を使う。** 理由:
- ほとんどのアプリは mouse イベントを処理する（tablet イベントだけでは
  mouseDown/Up を生成しないため、クリックとして認識されない可能性がある）
- CGEvent.h のドキュメントが (a) の手順を明示的に説明している
- Wacom ドライバの実績として (a) が標準的

## 8. 合成手順（ヘッダから導いた手順）

### 初回: Proximity イベント（接近）

```
1. CGEventCreateMouseEvent(source, kCGEventMouseMoved, position, .left)
2. CGEventSetIntegerValueField(event, kCGMouseEventSubtype,
     kCGEventMouseSubtypeTabletProximity)          ← 先に設定
3. proximity フィールドを設定:
   - kCGTabletProximityEventEnterProximity = 1（接近）
   - kCGTabletProximityEventPointerType = 1（ペン）
   - kCGTabletProximityEventDeviceID = 任意の固定値
   - kCGTabletProximityEventCapabilityMask = 0x0587
   - その他（VendorID, TabletID 等）= 任意の値
4. CGEventPost(kCGHIDEventTap, event)
```

### ストローク中: Mouse + TabletPoint

```
1. CGEventCreateMouseEvent(source, kCGEventLeftMouseDown/Dragged, position, .left)
2. CGEventSetIntegerValueField(event, kCGMouseEventSubtype,
     kCGEventMouseSubtypeTabletPoint)              ← 先に設定
3. tablet フィールドを設定:
   - kCGTabletEventPointPressure = 0.0–1.0
   - kCGMouseEventPressure = 同じ値（両方設定）
   - kCGTabletEventTiltX / TiltY = -1.0–1.0
   - kCGTabletEventDeviceID = proximity と同じ値
4. CGEventPost(kCGHIDEventTap, event)
```

### 終了: Proximity イベント（離脱）

```
proximity の EnterProximity を 0 にして送る。
```

## 9. 権限

| 関数 | 用途 | macOS |
|---|---|---|
| `CGPreflightPostEventAccess()` | 権限の有無を確認（プロンプトなし） | 10.15+ |
| `CGRequestPostEventAccess()` | 権限を要求（プロンプトあり） | 10.15+ |

Phase 0 で EventTap を使用済みであれば、アクセシビリティ権限は取得済みの可能性がある。
CGEventPost にも同じ権限が必要。

## 10. 未確認事項の一覧

| # | 内容 | 検証方法 |
|---|---|---|
| U1 | proximity なしで tabletPoint が受け付けられるか | proximity あり/なしで比較 |
| U2 | `kCGMouseEventPressure` と `kCGTabletEventPointPressure` のどちらをアプリが読むか | 片方ずつ設定して比較 |
| U3 | DeviceID に任意の値を使って動くか | 固定値で試行 |
| U4 | CGEvent の tilt 値域が本当に -1 to 1 か | 負の値を設定して NSEvent 側で確認 |
| U5 | `kCGHIDEventTap` vs `kCGSessionEventTap` のどちらに post すべきか | 両方試行 |
| U6 | capabilityMask を設定しなくても筆圧が通るか | マスク 0 で試行 |
